# Sandbox-Based Plotting Support

## Status

Accepted

## Context

Users want the ability to generate charts, plots, and other data visualizations dynamically by writing Python code on the visual canvas. The resulting figures need to be rendered natively inside the conversation chat interface.

Because the visual canvas executes agent actions and custom user-written Python code, running these plotting scripts directly on the host is a critical security risk. The execution must be securely isolated while still enabling the backend to capture, save, and serve the generated graphics back to the frontend.

## Considered Options

### 1. Sandbox Plot Capture using ArtifactSandboxSession (Chosen Option)

Leverage the `llm-sandbox` Docker execution environment to manage a warm pool of Docker containers pre-installed with standard plotting libraries (`matplotlib` and `plotly`). Instead of executing tools in standard interactive sessions, use `ArtifactSandboxSession`.

When an agent needs to create a plot:
- It calls a dynamically registered `generate_plot(python_code: str)` tool function.
- The Python script is run inside the sandbox. The user code calls standard show commands like `plt.show()` or `fig.show()`.
- `ArtifactSandboxSession` automatically intercepts these visualization frames, capturing them as base64-encoded strings in the execution results.
- The backend `PlotProvider` extracts the images, writes them as PNG/JPG files to a local `storage/plots/` folder on the host, and returns Markdown image tags (`![Plot](/api/static/plots/{filename})`) as the tool's result.
- The LLM is instructed via prompts to preserve these links in its final response, enabling the frontend chat interface to display them.

* **Pros:**
  * **Security:** All code execution remains strictly isolated within Docker containers.
  * **Developer UX:** Standard Python plotting code (like `plt.show()`) works out of the the box without custom file saving rules.
  * **Stability:** Decouples file management from the sandbox; the container doesn't need to persist or expose files directly to the host filesystem.
* **Cons:**
  * Requires a warm pool container configuration with `matplotlib` and `plotly` pre-installed, increasing container size.

### 2. Host-Side Code Execution

Execute the python code directly on the host machine using subprocesses and capture generated image files.

* **Pros:**
  * Simpler implementation.
  * No dependency on Docker sandbox features.
* **Cons:**
  * Critical security risk: arbitrary Python code generated by LLMs has access to the host environment, files, and networks.

### 3. Sandbox Volume Mounting with Manual Save

Run code in the sandbox container and require the user code to write files to a shared volume path (e.g. `/workspace/plot.png`), which is mounted to the host filesystem.

* **Pros:**
  * Simple sandbox output format.
* **Cons:**
  * High complexity for the user/agent writing the script, as it must coordinate filenames, paths, and formats explicitly.
  * Difficult to manage concurrency and cleanup across multiple conversation threads.

## Decision

**Option 1: Sandbox Plot Capture using ArtifactSandboxSession.**

We implement a `PlotProvider` class that interacts with `SandboxManager` to run plotting scripts in an `ArtifactSandboxSession`. The sandbox manager pre-warms the containers with `matplotlib` and `plotly` dependencies. The provider saves captured plots to `storage/plots/` and returns markdown image links.

To support this:
- We add an `enable_plotting` column to `agent_nodes`.
- We update `AgentFactory` to inject the `generate_plot` tool to any agent node (worker or router) with this capability enabled.
- We update agent prompts (especially routers) to ensure they preserve the markdown links exactly when returning their final answer.

## Consequences

* **Database Changes:**
  * Added `enable_plotting: BOOLEAN` column to `agent_nodes`.
* **Execution & Sandbox:**
  * Initialized the Docker container pool with `libraries=["matplotlib", "plotly"]`.
  * Used `ArtifactSandboxSession` in `PlotProvider` for intercepting plot events.
  * Assigned unique names of the format `sandbox-{uuid}` to sandbox containers to allow target-specific clean-up via `make clean-sandbox` (using Docker's `--filter "name=^sandbox-"`), avoiding accidental termination of other Python-based Docker containers.
  * Exposed a FastAPI static mount on the backend (`/api/static/plots`) pointing to `storage/plots/` to serve the images.
* **Agent Factory Instructions:**
  * Routers and workers are automatically supplied with instructions to preserve the generated image links (`![Plot](/api/static/plots/...)`) in their final text output.
* **Frontend Changes:**
  * Added the `Enable Plotting` capability checkbox in `AgentEditor` to easily toggle the option on worker or router nodes.
